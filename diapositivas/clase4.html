Hacer que la página reaccione a lo que hace el usuario: clics, teclas y envíos de formulario.

USIP · Curso de JavaScript · Clase 4
Bienvenida. Hasta ahora nuestro código se ejecutaba de arriba hacia abajo y terminaba. Hoy aprendemos a esperar acciones del usuario y responder a ellas: la base de cualquier aplicación interactiva.
Antes de empezar

¿El DOM ya está listo?

index.html<head>
  <script src="app.js"></script>  ← se ejecuta aquí
</head>
<body>
  <button id="btn">Clic</button> ← aún no existe
</body>

// app.js
const btn = document.querySelector("#btn");
console.log(btn); // null
btn.addEventListener("click", saludar);
// ❌ TypeError: Cannot read properties
//    of null (reading 'addEventListener')
1 · LecturaEl navegador lee el HTML de arriba hacia abajo.
2 · PausaAl encontrar un <script> clásico se detiene y lo ejecuta.
3 · nullLo que está más abajo todavía no existe: querySelector devuelve null.
Antes de escuchar eventos hay que asegurarse de que los elementos existen. Es el error más común al empezar: "Cannot read properties of null". No es un error de la lógica, es de CUÁNDO se ejecuta el script. Mostrarlo en vivo moviendo el script al head.
Antes de empezar · Soluciones

Formas de esperar al DOM

FormaCuándo se ejecuta¿DOM listo?
<script> al final de <body>Al llegar a esa línea; el HTML de arriba ya existe✔ Sí
DOMContentLoadedCuando el navegador terminó de leer el HTML✔ Sí
<script defer>Tras leer el HTML, en orden, justo antes de DOMContentLoaded✔ Sí
<script type="module">Igual que defer: los módulos ES son diferidos por defecto✔ Sí
<script async>Apenas termina de descargarse, sin orden✘ No garantizado
window · loadCuando también cargaron imágenes, CSS e iframes✔ Sí, pero tarda más
Las cuatro primeras resuelven el problema. async es para scripts independientes (analytics), no para código que toca el DOM. load solo se justifica si necesitamos medidas de imágenes ya cargadas. DOMContentLoaded se registra con document.addEventListener — es nuestro primer evento, lo detallamos enseguida.
Antes de empezar · ES modules

¿Sigue haciendo falta DOMContentLoaded?

Hoy · recomendado<head>
  <!-- A: módulo ES -->
  <script type="module" src="app.js"></script>
  <!-- B: script clásico -->
  <script src="app.js" defer></script>
</head>

// app.js — sin envolver nada ✔
const btn = document.querySelector("#btn");
btn.addEventListener("click", saludar);
Solo si no puedes usar module / deferdocument.addEventListener("DOMContentLoaded", () => {
  const btn = document.querySelector("#btn");
  btn.addEventListener("click", saludar);
});
  • Con type="module" o defer ya no hace falta.
  • Sí hace falta en un <script> clásico inline en el <head>.
  • type="module" necesita servidor (Live Server); con file:// falla.
Aclaración clave: usar sintaxis ES6 (let, const, flechas) NO cambia nada; lo que cambia es CÓMO se carga el script. type="module" lo vuelve diferido automáticamente (también los módulos inline). defer solo funciona con src, no en scripts inline. En el curso usaremos defer o type="module" y nos olvidamos de DOMContentLoaded. Si abren el HTML con doble clic (file://), el módulo falla por CORS: usar Live Server.
Conceptos

¿Qué es un evento?

Algo que ocurre en la página —un clic, una tecla, un envío— y a lo que podemos reaccionar ejecutando una función.

Anatomíaconst boton = document.querySelector("#btn");

boton.addEventListener("click", () => {
  alert("¡Hola!");
});
1 · Elemento¿Quién escucha? → boton
2 · Tipo de evento¿Qué esperamos? → "click"
3 · Handler¿Qué hacemos? → la función (un callback)
Relacionar con la clase pasada: el handler es un callback; el navegador lo llama cuando ocurre el evento. Mencionar que existe onclick="..." en el HTML, pero preferimos addEventListener: separa HTML de JS y permite varios listeners en el mismo elemento.

Mismo patrón en los cuatro: seleccionar el elemento, addEventListener con el tipo de evento y un callback. En submit, el listener va en el FORM, no en el botón.

Dato útil

mouseenter / mouseleave hacen lo mismo que mouseover / mouseout, pero no se repiten al pasar por los elementos hijos. Para efectos de hover suelen ser la mejor opción.

keydown: e.key dice qué tecla se presionó ("Enter", "Escape", "a"). mouseover/mouseout: JS solo agrega o quita la clase; el estilo vive en el CSS (y para un hover simple basta :hover en CSS, JS se justifica cuando hay lógica). DOMContentLoaded: recordar lo visto al inicio, solo hace falta si el script no usa defer ni type="module".

click en acción

//       <button id="sumar">+1</button>

Alternar modo oscuroconst tema = document.querySelector("#tema");

tema.addEventListener("click", () => {
  document.body.classList.toggle("oscuro");

    .classList.contains("oscuro");
  tema.textContent = oscuro
    ? "Modo claro" : "Modo oscuro";
});
Dos patrones que se repiten siempre: (1) modificar el texto de un elemento con textContent y (2) agregar/quitar clases con classList (add, remove, toggle, contains). El estilo vive en el CSS; JS solo cambia la clase. Hacerlo en vivo.
El objeto event

Lo que el evento nos cuenta

El parámetro edocument.addEventListener("keydown", (e) => {
  console.log(e.key); // "Enter", "a", "Escape"
  if (e.key === "Escape") cerrarModal();
});

boton.addEventListener("click", (e) => {
  console.log(e.target); // el elemento clicado
  console.log(e.type);   // "click"
});

enlace.addEventListener("click", (e) => {
  e.preventDefault(); // no navega
});
  • e.target — el elemento que originó el evento
  • e.type — el tipo de evento
  • e.key — la tecla presionada
  • e.preventDefault() — cancela la acción por defecto del navegador
  • e.stopPropagation() — evita que el evento suba a los padres
El navegador llama a nuestro handler pasándole un objeto con toda la información del evento. Por convención lo llamamos e o event. preventDefault será clave en los formularios (evita que la página se recargue al enviar).
Formularios · submit

Capturar el envío del formulario

HTML<form id="registro">
  <input name="nombre" required>
  <input name="email" type="email">
  <select name="curso">
    <option>JavaScript</option>
    <option>Python</option>
  </select>
  <button>Registrarme</button>
</form>
<p id="mensaje"></p>
JavaScriptconst form = document.querySelector("#registro");

form.addEventListener("submit", (e) => {
  e.preventDefault(); // ¡sin recargar!

  const datos = Object.fromEntries(new FormData(form));
  console.log(datos);
  // { nombre: "Ana", email: "…", curso: "…" }

  form.reset();
});
Escuchamos submit en el form, no click en el botón: así también funciona al presionar Enter. FormData lee todos los campos por su name y Object.fromEntries (clase 2) lo convierte en un objeto normal. Los atributos required y type="email" son una primera validación gratis del navegador.

Validación

Validar antes de enviar

submit con validaciónform.addEventListener("submit", (e) => {
  e.preventDefault();
  const nombre = form.elements.nombre.value.trim();
  const email = form.elements.email.value.trim();
  const errores = [];

  if (nombre.length < 3) errores.push("Nombre corto");
  if (!email.includes("@")) errores.push("Email inválido");

  if (errores.length > 0) {
    mensaje.textContent = errores.join(" · ");
    return; // detenemos aquí
  }
  enviar({ nombre, email }); // fetch de la clase 3
});
  • trim() quita espacios al inicio y al final
  • Acumulamos los errores en un array
  • return corta la función si algo falla
  • Si todo está bien → enviamos con fetch
Todo lo aprendido se junta aquí: arrays y join (clase 2), funciones y return (clase 2), fetch (clase 3), eventos (hoy). Importante: la validación en el navegador mejora la experiencia, pero el servidor siempre debe validar de nuevo.

    turno = turno === "X" ? "O" : "X";

});

row,col de cada casilla

ganadorempatereiniciar
Los atributos data-* guardan información propia en el HTML. data-row y data-col indican la posición de cada casilla. Para obtener un elemento por esos atributos usamos un selector de atributo: '[data-row="1"][data-col="1"]' (comillas simples afuera, dobles adentro). En JS se leen con dataset: data-row → celda.dataset.row. Ojo: siempre llegan como texto ("1"); si necesitamos número, Number(celda.dataset.row). Construirlo en vivo y ver en consola qué fila y columna se clicó. La próxima clase usamos row y col para detectar al ganador.
