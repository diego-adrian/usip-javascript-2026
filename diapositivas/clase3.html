Continuamos con funciones

Funciones que reciben funciones

Función de orden superiorfunction operar(a, b, operacion) {
  return operacion(a, b);
}

const sumar = (x, y) => x + y;
const multiplicar = (x, y) => x * y;

operar(4, 2, sumar);        // 6
operar(4, 2, multiplicar);  // 8
operar(4, 2, (x, y) => x - y); // 2
  • En JS las funciones son valores: se guardan en variables y se pasan como argumentos
  • Una función que recibe otra es una función de orden superior
  • La función que se pasa se llama callback
  • Ya los usamos: map, filter, forEach
  • Los callbacks son la base de la asincronía
Puente con la clase anterior. Observar que pasamos "sumar" sin paréntesis: pasamos la función, no su resultado. Si escribimos sumar() la estaríamos ejecutando.
Cómo se ejecuta el código

Síncrono vs asíncrono

Síncrono: línea por líneaconsole.log("1. Inicio");
console.log("2. Proceso");
console.log("3. Fin");

// 1 → 2 → 3
Asíncrono: no bloqueaconsole.log("1. Inicio");
setTimeout(() => {
  console.log("2. Después de 2s");
}, 2000);
console.log("3. Fin");

// 1 → 3 → 2

JavaScript tiene un solo hilo. Las tareas lentas —peticiones, temporizadores, lectura de archivos— se delegan y su resultado vuelve después gracias al event loop.

Pedir al grupo que adivine el orden de la derecha antes de mostrar el resultado. Analogía: pedir comida en un restaurante. El mesero (JS) no se queda parado en la cocina esperando tu plato: toma otros pedidos y te lo trae cuando está listo.

  • Cada paso depende del resultado del anterior
  • El código crece hacia la derecha
  • Hay que manejar el error en cada nivel
  • Difícil de leer y mantener
  • La solución de ES6: Promesas
Así se escribía código asíncrono antes de 2015 (y aún se ve en código antiguo de Node.js). No hace falta memorizarlo: lo importante es entender el problema que resuelven las promesas.
ES2015

¿Qué es una Promesa?

Un objeto que representa un valor que llegará en el futuro… o un error.

pendingPendiente: todavía esperando
fulfilledCumplida: resolve(valor) → .then
rejectedRechazada: reject(error) → .catch
Crear y consumirconst promesa = new Promise((resolve, reject) => {
  setTimeout(() => {
    const ok = Math.random() > 0.5;
    ok ? resolve("¡Listo!") : reject("Falló");
  }, 1000);
});

promesa
  .then(valor => console.log(valor))
  .catch(error => console.log(error));
Analogía: el ticket con número que te dan en un local de comida rápida. Es una promesa: aún no tienes la comida (pending), pero cuando llamen tu número la recibes (fulfilled) o te dicen que se acabó (rejected). Una promesa solo cambia de estado una vez. En la práctica casi nunca creamos promesas: las consumimos (fetch devuelve una).
Forma clásica · then / catch

Consumir una API con fetch

jsonplaceholder.typicode.comfetch("https://jsonplaceholder.typicode.com/users/1")
  .then(res => {
    if (!res.ok) throw new Error("HTTP " + res.status);
    return res.json();
  })
  .then(usuario => {
    console.log(usuario.name); // "Leanne Graham"
  })
  .catch(error => console.error(error))
  .finally(() => console.log("Terminado"));
  • fetch devuelve una promesa
  • res.json() también
  • Cada then recibe lo que retornó el anterior
  • Un solo catch atrapa errores de toda la cadena
  • finally se ejecuta siempre
Probarlo en vivo en la consola del navegador. Ojo: fetch solo rechaza la promesa si falla la red; un 404 o 500 llega al then. Por eso revisamos res.ok y lanzamos el error manualmente. Otros endpoints para probar: /posts, /todos, /comments?postId=1.
Forma moderna · ES2017

async / await

El mismo ejemploconst API = "https://jsonplaceholder.typicode.com";

async function obtenerUsuario(id) {
  try {
    const res = await fetch(`${API}/users/${id}`);
    if (!res.ok) throw new Error("HTTP " + res.status);
    const usuario = await res.json();
    console.log(usuario.name);
  } catch (error) {
    console.error("Algo falló:", error.message);
  }
}

obtenerUsuario(1);
  • async hace que la función devuelva una promesa
  • await pausa la función (no la página) hasta que la promesa se resuelva
  • Errores con try / catch
  • Se lee de arriba hacia abajo: adiós pirámide
Es exactamente lo mismo que la diapositiva anterior, con otra sintaxis: por debajo siguen siendo promesas. await solo se puede usar dentro de una función async (o en el nivel superior de un módulo). Es la forma recomendada hoy.

  fetch(`${API}/users`).then(r => r.json()),

No son enemigos: async/await está construido sobre promesas y se pueden combinar (como en el ejemplo de Promise.all). Promise.all lanza todas las peticiones a la vez y espera a que terminen todas; si una falla, falla todo.
Introducción a formularios

Leer lo que escribe el usuario

HTML<form id="form">
  <input name="titulo" placeholder="Título">
  <textarea name="cuerpo"></textarea>
  <button type="submit">Publicar</button>
</form>
JavaScriptconst form = document.querySelector("#form");
const titulo = form.elements.titulo;

titulo.value;        // lo que escribió
titulo.value = "";   // limpiar el campo
titulo.focus();      // poner el cursor
form.reset();        // limpiar todo
  • form.elements da acceso a cada campo por su atributo name
  • La propiedad .value siempre es un string → usa Number() si necesitas un número
Los formularios son la forma principal en que el usuario nos da datos. Recalcar que .value es siempre texto: "5" + "5" = "55". La próxima clase los veremos a fondo junto con los eventos.
Uniendo todo

Enviar un formulario a la API

POST a /postsform.addEventListener("submit", async (e) => {
  e.preventDefault(); // evita recargar
  const datos = {
    title: form.elements.titulo.value,
    body: form.elements.cuerpo.value,
  };
  const res = await fetch(`${API}/posts`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(datos),
  });
  console.log(await res.json()); // { id: 101, ... }
});
  • submit ocurre al enviar el formulario
  • preventDefault() evita que la página se recargue
  • jsonplaceholder simula el guardado y responde con id: 101
